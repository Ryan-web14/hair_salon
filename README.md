# Hair Salon Booking API

A REST API for salon appointment booking, built with Spring Boot 3.4 and Java 21. It handles client self-booking, barber and esthetician scheduling, availability generation, and automated reminders by email and SMS.

## Features

- **Appointment booking** with availability computed from staff schedules, check-in, cancellation, and completion tracking
- **Two service lines**: barbers (haircuts) and estheticians (esthetic services), each with their own staff, catalogue, and schedules
- **Scheduling**: per-staff schedules, bulk schedule creation from templates, and time-off handling
- **Role-based access**: client, barber, esthetician, manager, and admin, enforced per endpoint
- **Authentication**: JWT with stateful session tracking and a password reset flow using single-use tokens
- **Notifications**: transactional email, SMS through Twilio and Infobip, and calendar invites generated with iCal4j
- **Client history** recording past visits per client

## Architecture

The code follows a layered Spring Boot structure, with DTOs at the boundary so JPA entities are never exposed over HTTP.

```
Controller      REST endpoints, role checks via @PreAuthorize
    │
    ▼
Service         interface + serviceImpl, business rules
    │
    ▼
Mapper          entity <-> DTO translation
    │
    ▼
Repository      Spring Data JPA
    │
    ▼
PostgreSQL
```

Cross-cutting pieces sit alongside it:

- `security/` holds the JWT filter, `SecurityConfig`, the password encoder, and a `UserDetailsService` backed by the user table
- `exception/` holds typed exceptions and a `@ControllerAdvice` global handler producing a consistent error payload
- `generator/` and `annotation/` provide generated public identifiers, so database primary keys are never exposed in URLs

## Endpoints

All routes are versioned under `/v1`:

| Area | Base path |
|---|---|
| Authentication | `/v1/auth` |
| Current user | `/v1/me` |
| Users and roles | `/v1/user`, `/v1/role` |
| Clients | `/v1/client` |
| Barbers | `/v1/barber` |
| Estheticians | `/v1/esthetician` |

| Esthetic services | `/v1/esthetic` |
| Schedules | `/v1/schedule` |
| Availability | `/v1/availability` |
| Appointments | `/v1/appointment` |
| Sessions | `/v1/session` |

## Running locally

```bash
git clone https://github.com/Ryan-web14/hair_salon.git
cd hair_salon/hairsalon
./mvnw spring-boot:run
```

Requires JDK 21 and a reachable PostgreSQL instance.

Configuration is read from the environment, never committed. Create a `.env` file at `hairsalon/`:

```properties
SPRING_PROFILES_ACTIVE=dev

JDBC_DATABASE_URL=jdbc:postgresql://localhost:5432/hairsalon
JDBC_DATABASE_USERNAME=
JDBC_DATABASE_PASSWORD=

SPRING_MAIL_HOST=
SPRING_MAIL_PORT=
SPRING_MAIL_USERNAME=
SPRING_MAIL_PASSWORD=

TWILIO_ACCOUNT_SID=
TWILIO_AUTH_TOKEN=
INFO_BIP_API_KEY=
```

Three profiles are defined: `dev`, `prod`, and the defaults in `application.properties`.

## Deployment

A `Procfile` and `system.properties` are included for a container-based platform:

```
web: java -Dserver.port=$PORT $JAVA_OPTS -jar target/*.jar
```

Build the artifact with `./mvnw clean package`.

## Project layout

```
hairsalon/src/main/java/com/sni/hairsalon/
  controller/      REST endpoints
  service/         interfaces
    serviceImpl/   implementations
  repository/      Spring Data JPA
  model/           JPA entities
  dto/request/     inbound payloads
  dto/response/    outbound payloads
  mapper/          entity <-> DTO
  security/        JWT filter, config, user details
  exception/       typed exceptions, global handler
  generator/       public id generation
  utils/           validation helpers

hairsalon/src/main/resources/
  application*.properties
  db/migration/    Flyway scripts
```

## Known gaps

- No automated test suite. The test dependencies (JUnit 5, Mockito, AssertJ, H2) are declared but `src/test` is empty.
- No OpenAPI or Swagger documentation yet.
- Only one Flyway migration is versioned; the initial schema is generated by Hibernate.
